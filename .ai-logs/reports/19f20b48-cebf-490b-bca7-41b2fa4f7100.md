## Summary

Fixed a bug where the sentence-review screen was stuck on "Câu 1 / 17" — the "Tiếp tục" (Continue) button either did nothing or jumped straight to the Practice screen instead of advancing to the next sentence. Root cause: `SentenceDetail` route params only ever carried a single `sentence` plus a hardcoded `index: 0`, so the screen had no data or logic to move to sentence 2+. Fixed by passing the full `sentences` array through navigation and adding next-sentence navigation logic.

## Changed files

- `src/app/navigation/types.ts` — Changed the `SentenceDetail` route param shape from `{sentence, index, total, practice}` to `{sentences, index, practice}`. `total` is now derived from `sentences.length` instead of being passed separately, removing a source of index/total drift.
- `src/modules/lesson/LessonResultScreen.tsx` — `openFirstSentence()` now passes the full `sentences` array (was passing only `sentences[0]` plus a hardcoded `total`).
- `src/modules/lesson/SavedLessonDetailScreen.tsx` — Same change as above, for the saved-lesson entry point.
- `src/modules/lesson/SentenceDetailScreen.tsx` — Derives `sentence = sentences[index]` and `total = sentences.length` from the new params. The "Tiếp tục" button now navigates back to `SentenceDetail` with `index + 1` when not on the last sentence, and only navigates to `Practice` once the last sentence is reached (and practice questions exist).
- `src/modules/lesson/__tests__/LearningDetailScreens.test.tsx` — Updated the `SentenceDetailScreen` test's route params to match the new `{sentences, index, practice}` shape.

## New dependencies

None.

## User review

- Root cause and fix were verified via static analysis (code-review-graph MCP), `tsc --noEmit` (no new type errors vs. an 11-error pre-existing baseline), and `jest` (`src/modules/lesson` — 4 suites / 11 tests passing). **Not yet verified on a running simulator/device** — please manually confirm that tapping "Tiếp tục" now steps through all 17 sentences and correctly reaches Practice at the end.
- Behavior change: previously, if `practice.length > 0`, tapping Continue on *any* sentence (including sentence 1) skipped straight to Practice. Now it only does so on the *last* sentence. If skipping straight to practice from sentence 1 was intentional product behavior in some flow, this change alters that — worth double-checking with product intent.
