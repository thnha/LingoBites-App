## Summary

Investigated why the "Bài học" (Lessons) screen shows an empty list under the "Ngữ pháp" / "Từ vựng" / "Thành ngữ" filter tabs despite having saved lessons. Root cause: `useLibraryStore.ts` assigns each lesson's subject/category using `SUBJECT_ROTATION[index % 4]` — a fake round-robin based on list position, not real lesson content. With only 1 saved lesson, every filter except "Ngữ pháp" (grammar, position 0) can never match, producing the "Không tìm thấy bài học phù hợp" empty state seen in the screenshot.

Discussed the fix approach with the user (via AskUserQuestion) and wrote a full implementation plan — no code was changed yet, per user's request to defer execution ("để làm sau đi").

## Changed files

- `docs/superpowers/plans/2026-08-08-lesson-category.md` (created) — Implementation plan for the fix: add a real `category` column to the `lessons` SQLite table, derive it in `LessonRepository.saveLesson()` from actual `grammar_points`/`vocabulary` counts in the AI output, and update `useLibraryStore.ts` to filter/label lessons from that real field instead of list-position rotation. Includes exact code diffs, new/updated Jest tests, and a manual smoke-test checklist, broken into 4 reviewable tasks.

No application code files were modified in this session — only the plan document.

## User review

- Known accepted limitation baked into the plan (explicitly confirmed with the user): the "Thành ngữ" (idioms) and "Hội thoại" (conversation) filter tabs will keep showing the empty state even after the fix, because the AI output schema (`ai-output-v1.ts`) has no field to detect idiom/conversation content — only grammar vs. vocabulary can be auto-classified from the data available. This is a scope decision, not an oversight; flagged for user awareness in case it resurfaces as a "bug report" later.
- Plan proposes a `ALTER TABLE lessons ADD COLUMN IF NOT EXISTS ...` migration, which requires SQLite ≥ 3.35 (bundled by `react-native-quick-sqlite`) — worth double-checking against the actual bundled version before executing, since `runMigrations()` re-runs this statement on every app launch and must be idempotent.
